# First Encounter hands-first working rules

Read `01_DESIGN_NOTE.md` and `02_CODEX_BUILD_SPEC.md`. This is a new, independent hands-first action-game build, not an authorization to edit or merge the original FEG, Lab, ROOM, ZANT, DPA or body-tool repositories.

Teddy approved a new repository and edits to this game's copied ROOM action runtime. The latest direction is explicit: controls are experimental, shared combatants are mandatory, hands first. Historical donor comments and the superseded prebuild report describe older scopes. Preserve those originals; do not treat their old keybindings or a Lab-only edit prohibition as the new game's creative specification.

- Confirm the independent Git root and remote before writes/pushes. Never write to a protected original checkout. Read-only upstream inspection is allowed.
- `vendor/`, `assets/source/`, and imported source receipts remain byte-identical. Work under `game/` and newly authored directories. Derived assets record origin and transformation.
- One shared actor/action authority. Input buttons, NPC decisions and sprites are adapters, not alternate physics.
- Controls profile Sketch A and all tuning constants are replaceable experiments. Do not hard-wire buttons inside the resolver.
- One lead owns shared integration files and publishing. At most three workers at once. File ownership first; independent verifier does not patch production or weaken tests.
- No runtime online AI, server requirement, paid API dependency, new engine, destructive city, weapons, clinch or Punchline implementation in this first scope.
- Stop on a genuine authority, missing-source, destructive or consent blocker; otherwise proceed through the internal implementation gates without repeatedly asking the owner.
- Label inherited, newly measured, proposed and unverified evidence separately. Timeouts and unavailable Windows/hardware tests are not passes.
- No force push, history rewrite, secrets in files, or automatic merge to originals. An initial scaffold commit in the new repo and a bounded implementation review-branch push are in scope after verification.
- Agent role instructions are not proof of tool permissions or of an agent actually being spawned. Report the real execution method.
- End by delivering an actual playable and evidence, not by presenting this specification as the completed game.
